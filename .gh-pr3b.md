### why

`youtubei.js` + `isolated-vm` pull native build dependencies into the docker image (`python3`, `alpine-sdk`), and the poToken / session-server flow adds a second service to run next to the api just to keep youtube extraction alive. this replaces both with a vendored pure-JS engine that talks to the innertube api in-process, so youtube keeps working in the stock image and `pnpm install` no longer builds a native module.

this is a large and opinionated change that **removes existing configuration**, so it probably deserves a maintainer decision before going in. it is independent of the two sibling prs.

### what changes

- `services/youtube.js` no longer creates an innertube client. extraction is one call into the engine (`helpers/ytubedl.js`), and the adapter returns the same JSON shape the existing format-selection code already consumed — selection, metadata, dubs, subtitles, filename attributes and the picker are untouched.
- formats carry codec family aliases (`avc1` / `vp9` / `av01`), because vp9's full innertube name (`vp09.00.51.03`) would otherwise never match the codec haystack.
- widevine formats are skipped instead of advertised; a fully DRM-protected video reports `youtube.drm` instead of handing out undecryptable urls.
- captions locked with `exp=xpe` are dropped instead of failing the whole merge — the same intent as the old hls-subtitle fallback.
- `youtubeHLS` still works. when the engine has no manifest, the request degrades to the progressive path instead of failing.

### env vars

removed: `YOUTUBE_SESSION_SERVER`, `YOUTUBE_SESSION_INNERTUBE_CLIENT`, `CUSTOM_INNERTUBE_CLIENT`, `YOUTUBE_PLAYER_ID`.

added: `YOUTUBE_ENGINE` (`ytubedl` by default, `off` returns `service.unsupported`) and `YTUBEDL_COOKIES` (path to a netscape `cookies.txt`). cookies from `cookies.json` still take precedence and rotate per request.

`docs/api-env-variables.md`, the dockerfile and `api/README.md` are updated, and there's a new `youtube.engine` error string (en + ru).

### static analysis

deepsource found two real issues in the adapter (`captions` destructured but unused, and the injected `fetchImpl` parameter shadowing `url`); both are fixed. every remaining finding is inside the vendored engine (`Buffer.allocUnsafe` in its segment downloader, `process.exit()` in the engine's own cli, unused catch bindings, regex escaping). `.deepsource.toml` now excludes `api/src/processing/services/vendor/**`, since that tree is copied verbatim from the engine's build output and refreshed wholesale.

### verification

- an offline harness passed 14/14 checks: adapter shape, codec aliases, dub and metadata mapping, hls degradation, error classification, cookie and dispatcher forwarding. i left the harness out of this pr because it also covers the threads engine from the sibling pr — happy to include it if wanted.
- `node -e "import('./src/processing/match.js')"` loads the full service graph with the new engine.
- i have not run `api/src/util/test` against live youtube from here; `api/src/util/tests/youtube.json` should cover that in ci.
