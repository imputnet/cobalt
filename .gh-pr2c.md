### what

adds `threads` support for public posts with a video or image:

- `threads.com/@user/post/CODE`, `threads.com/@user/post/CODE/slug`, `threads.com/post/CODE` and the legacy `threads.com/t/CODE`
- `threads.net` is aliased to the canonical `threads.com` host
- multi-media posts return a picker with proxied thumbnails; a single video redirects like the other video services, a single image tunnels
- text-only and missing posts return `content.post.unavailable`

### implementation

`services/threads.js` is 96 lines and follows the shape of the other services: get the media, then return `urls` + `filename`, a `picker`, or an error.

extraction goes through a vendored engine (`services/vendor/threads-downloader-engine.cjs`, MIT, license file included), because the logged-out graphql flow needs several fallbacks. it is ~1.6k lines and dominates this diff. **if keeping the dependency surface small matters more, i'm happy to rewrite this as a minimal in-tree implementation against cobalt's own `fetch` helpers** — the service only ever calls `extract()`.

### tests

`api/src/util/tests/threads.json`, 11 cases: video post, post link without a username, legacy `t/` link, single image, carousel, slugged video, multi-item post with and without slug, text-only post, nonexistent post. they're marked `canFail` because they depend on threads not rate-limiting the runner.

- offline checks: the engine module loads (v1.0.0), `extract`/`extractOrThrow` are exposed, url routing resolves every pattern above including the `threads.net/t/…` aliasing, and a failing extraction falls through to `content.post.unavailable` instead of throwing.
- the live fixtures were not run from this environment.

### static analysis

deepsource flagged one issue in the service (`username` was destructured but unused — the engine resolves everything from the shortcode, so the parameter is gone). its remaining findings are all inside the vendored `.cjs` (unused catch bindings, `"use strict"` placement in the UMD wrapper). `.deepsource.toml` now excludes `api/src/processing/services/vendor/**`, since that file is copied verbatim from the engine's build output and refreshed wholesale. the sibling youtube pr makes the same config change, so whichever lands first makes the other a no-op.
